Database Schema

  • wp_pade_queue: post queue records with payload, status lifecycle, retries, timestamps.
  • wp_pade_logs: diagnostic log entries containing platform, HTTP code, full raw response JSON, and success flag.
  • wp_pade_images: tracks image usage (`last_used_at`) for bulk image mode duplicate prevention.

Queue Lifecycle

pending → approved → scheduled → processing → completed / failed

Retry policy: up to 3 total attempts (initial + 2 retries).

Data Flow

WordPress Publish Event
    -> Queue Engine inserts wp_pade_queue row
    -> Scheduler cron triggers processing
    -> Queue item enters processing
    -> AI Engine generates caption (template placeholders)
    -> Router dispatches payload to selected platform module
    -> Platform module returns response and Logger::log() writes wp_pade_logs
    -> Queue status updated to completed or failed/scheduled(retry)

How to Add a New Platform Class

  1. Create `platforms/class-yourplatform.php` with `PADE_Platform_Yourplatform::send( $payload )`.
  2. Inside `send()`, perform API request and call `PADE_Logger::log()` with full response data.
  3. Update `PADE_Router::dispatch()` map with your new platform key and class name.
  4. Add settings fields in the settings page for token and prompt template.

AI Integration

  • Centralized in `PADE_AI_Engine`.
  • Uses admin-configured OpenAI API key, model, and max tokens.
  • Uses platform prompt templates with placeholders:
    • {post_title}
    • {post_content}
    • {platform_name}
  • Stores last AI response for diagnostics preview.
